# JunkItOut Android Application — Security & Access Control Audit

## 1. Executive Security Assessment

A comprehensive security review of the JunkItOut Android application (`:app` Customer App and `:driver` Partner App) and central Node.js backend was performed.

---

## 2. Key Security Audit Findings

### A. APK & Secret Management (PASS ✅)
- **Zero Embedded Backend Secrets**: No database passwords, JWT secrets, or SMS gateway API keys exist in client APK/AAB files.
- **Client BuildConfig Injection**: Public client-safe keys (`API_BASE_URL`, `RAZORPAY_KEY_ID`, `GOOGLE_MAPS_API_KEY`) are injected via `local.properties` / `BuildConfig`.

### B. App Signing & Play Integrity (PASS ✅)
- Both `:app` and `:driver` release builds are signed using the authentic original production key:
  - **Keystore File**: `release-key.jks`
  - **Key Alias**: `key0`
  - **SHA1 Certificate Fingerprint**: `95:1C:8F:C1:02:8F:91:A6:94:37:31:28:27:E0:2E:22:94:12:75:F6`

### C. Authentication & Token Security (PASS ✅)
- **JWT Verification**: Customer endpoints require `Authorization: Bearer <userJwt>` and driver endpoints require `Authorization: Bearer <driverJwt>`.
- **Server Role Isolation**: Drivers cannot invoke customer endpoints with driver tokens and vice versa.

### D. Payment Security (PASS ✅)
- **HMAC-SHA256 Server Signature Verification**: Online payments via Razorpay are verified on the backend using `crypto.createHmac('sha256', env.RAZORPAY_KEY_SECRET)`. Client payment callbacks alone are never trusted as proof of payment.

### E. Doorstep Pickup Verification (PASS ✅)
- **4-Digit Pickup Verification OTP**: Automatically generated by backend on order creation (`pickup_otp`).
- Collector must input customer's OTP at doorstep to unlock the completion workflow, preventing fraudulent trip completions.

### F. Network & Transport Security (PASS ✅)
- All production traffic flows strictly over HTTPS (`https://junkitout-android.onrender.com`).
